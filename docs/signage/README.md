# KMUCS 뉴스 사이니지

alumni 기사와 저장소의 설정을 사용해 Windows PC 한 대에서 여러 세로 모니터를 재생한다. 세션마다 목록 화면과 상세 화면을 배정한다. 기본 해상도는 1080×1920이며 실제 창 크기와 Windows 배율에 맞춰 같은 비율로 축소한다.

## 문서 안내

- [운영과 설치](operations.md): 설치 파일 생성, Windows 설정, 전체 화면, 자동 실행, 장애 대응
- [콘텐츠와 설정](configuration.md): 기사·요약·시간 변경, 세션 추가, 배포 규칙
- [개발과 검증](development.md): 모노레포 구조, 시간 동기화, 메모리 실측과 장시간 검사, 테스트, 호환성

## 화면에서 편성하기

배포 후 운영자는 `https://alumni.cs.kookmin.ac.kr/signage/setup/`를 북마크해 연다. 일반 사이트 메뉴에는 연결하지 않고 `/signage/` 경로를 사이트맵에서 제외한다. 편성·미리보기 HTML에는 `noindex`를 지정한다. 이는 검색 노출을 줄이는 설정이며 로그인 보호는 아니다. 주소를 아는 사람은 열 수 있지만, 이 페이지에서 운영 설정을 직접 저장하거나 배포할 수는 없다.

`/signage/setup/`에서 공개 뉴스레터에 요약이 있는 기사를 검색해 선택하고 2대(목록과 상세), 3대(목록과 상세 2개) 또는 4대(두 쌍)에 나눠 담는다. 순서와 재생시간을 조절하고 미리본 뒤 설정 파일을 내려받는다. 파일을 `src/content/config/signage.json`에 반영하고 기존 사이트 배포를 수행한다. 다운로드 자체가 운영 화면을 바꾸지는 않는다.

Windows 앱의 **모니터 한 번에 배정**에서 세션을 선택하고 **빠른 배정 → 저장하고 실행**으로 연결한다. 자세한 흐름은 [콘텐츠와 설정](configuration.md#웹에서-2대3대4대-편성하기)을 참고한다.

## 먼저 볼 파일

| 목적 | 파일 |
| --- | --- |
| 세션, 재생 순서, 시간 설정 | `src/content/config/signage.json` |
| 뉴스레터별 기본 기사 목록 | `src/content/news/*.md`의 `articleIds`, 생략 시 HTML 요약 링크 순서 |
| 상세 요약 원본 | `src/content/news/*.md`의 HTML 기사 카드 |
| 기사 제목, 이미지, 목록 소개 | `src/content/articles/*.mdx` |
| 정적 데이터 생성 | `src/lib/signage.ts` |
| 공개 데이터 | `/signage/feed.json` |
| 웹 미리보기 | `/signage/` |
| 공용 화면과 타임라인 | `packages/signage-player/src/` |
| Windows 앱 | `apps/signage-desktop/` |

## 빠른 개발 시작

Node.js 22.12 이상과 pnpm 10.33.3을 사용한다. 모든 명령은 저장소 루트에서 실행한다.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

출력된 개발 서버 주소의 `/signage/`를 연다. 다른 터미널에서 다음 명령을 실행하면 한 모니터에서도 목록·상세 창을 나란히 확인할 수 있다.

```sh
pnpm signage:demo
```

데스크톱 개발 모드는 기본적으로 `http://localhost:4321/signage/feed.json`을 읽는다. 포트가 다르면 [운영 문서의 환경변수](operations.md#개발용-주소)를 설정한다. 첫 실행은 Electron 런타임 다운로드 때문에 시간이 걸릴 수 있다.

## 운영 모델

1. Codex 또는 편집기로 기사와 설정을 수정한다.
2. `/signage/`에서 기사 버튼을 눌러 각 화면의 글자와 이미지를 확인한다.
3. 테스트와 빌드를 실행한 뒤 기존 alumni 배포 절차로 게시한다.
4. Windows 앱이 새 데이터와 이미지·폰트를 받는다.
5. 모든 실행 화면의 준비가 끝나면 세션별 기존 반복 경계에서 함께 교체한다.

설정과 콘텐츠를 바꿀 때는 Windows 앱을 다시 설치하지 않는다. 재생 화면 코드, 데이터 형식 또는 Electron 코드를 바꾸면 앱 새 버전을 배포한다.

## 실제로 띄우는 순서

1. 최초 한 번은 사이니지 코드와 설정을 저장소 `main`에 반영해 기존 GitHub Pages 배포를 완료한다. 로컬 `localhost` 미리보기만으로 운영 사이트가 바뀌지는 않는다. `/signage/setup/`, `/signage/`, `/signage/feed.json`이 alumni 도메인에서 열리는지 확인한다.
2. 현재 3호의 기사는 `src/content/news/newsletter-003.md`의 HTML 요약 링크에서 자동으로 읽는다. 요약은 각 기사 카드의 `<p>`를 수정한다. 추가 요약 파일은 필요 없다.
3. 편성 페이지에서 2·3·4대 구성, 기사, 순서와 시간을 지정한다. 내려받은 `signage.json`을 `src/content/config/signage.json`에 반영하고 사이트를 배포한다. 기본 파일은 목록 1대와 상세 1대의 2대 구성이다. 3대 구성은 세션의 `detailCount: 2`, 4대는 독립 세션 두 개가 필요하다.
4. Windows에 KMUCS News Sinage 1.2.3 이상을 설치하고 모니터를 확장·세로로 설정한다. 앱에서 해당 세션과 2·3·4대 구성을 선택해 빠른 배정한 뒤 저장하고 실행한다. 모두 준비되면 전체 화면으로 재생한다.
5. 이후 기사·요약·시간을 수정하고 배포하면 앱이 기본 60초마다 변경을 확인한다. 에셋 준비가 끝나고 현재 반복이 끝나는 시점에 자동 교체하며 재실행할 필요가 없다.

### 다음 호수로 바꿀 때

`src/content/news/newsletter-004.md`를 공개 HTML 뉴스레터로 만들고 기사 카드 링크와 요약을 넣는다. 필요하면 `articleIds`에 기본 순서를 적는다. 그다음 `src/content/config/signage.json`에서 기존 세션의 `id`와 `startsAt`은 유지하고 `newsletterId`, `title`, `issue`, `dateLabel`을 새 호수에 맞춘다.

설정에 `items`가 있으면 그 목록이 우선한다. 새 호수 기사 ID로 바꾸거나 `items`를 제거해야 새 뉴스레터 기본 목록을 사용한다. `newsletterId`만 바꾸고 이전 `items`를 남기면 이전 기사가 계속 나온다. 편성 페이지의 뉴스레터 필터는 검색 범위만 바꾸며 세션의 호수·제목을 자동 변경하지 않는다.

Codex에는 다음과 같이 요청하면 된다. “4호를 기존 lobby-a 세션에 적용해 줘. 호수와 제목·날짜를 바꾸고, 기사 목록은 4호 기준으로 교체해 줘. 모니터 구성과 재생시간은 유지해 줘.” 변경 확인과 배포 후 앱이 자동 수신한다.

## 첫 버전의 범위

별도 서버, 사용자 로그인, 실시간 관리자 웹, 기기 간 네트워크 동기화는 포함하지 않는다. 운영 동기화 대상은 한 PC의 여러 창이다. 브라우저 미리보기의 별도 탭들은 Windows 앱처럼 준비 확인을 주고받지 않는다.

원격 설정 변경은 사이트 배포와 주기적 확인을 거친다. 설치 파일은 현재 코드 서명 인증서 없이 생성된다. 실제 Windows 장비 검증 상태는 [개발 문서](development.md#검증-기록)를 확인한다.


## 숫자 호수가 없는 월호 발행

숫자 호수와 월호를 함께 운영할 수 있다. 짝수월의 `newsletter-004`와 홀수월의 `newsletter-2026-09`는 서로 다른 뉴스레터다. 발행 목록은 파일명이나 숫자 호수가 아닌 `publishedAt`으로 정렬한다.

1. `/tools/newsletter/`에서 **호수 또는 월호**에 `9월호`, **발행 라벨**에 `2026.09`, **부제**에 `KMUCS 9월호 뉴스레터`를 입력한다. 실제 발행일도 지정한다. 기사별 요약을 본문에 넣는다.
2. 뉴스 등록 커맨드는 `src/content/news/newsletter-2026-09.md`와 영문·숫자 경로의 표지 이미지를 만든다. 숫자 `004`를 입력하면 기존처럼 `newsletter-004`를 만든다. 커맨드를 실행하는 것은 파일 생성과 커밋이며, 운영 반영에는 사이트 배포가 필요하다.
3. `src/content/config/signage.json`의 해당 세션에서 다음 네 필드를 바꾼다. `id`, `startsAt`, 모니터 구성과 시간 설정은 유지한다.

```json
{
  "newsletterId": "newsletter-2026-09",
  "title": "KMUCS 9월호 뉴스레터",
  "issue": "9월호",
  "dateLabel": "2026.09"
}
```

위 JSON은 변경할 필드만 보여 준다. 기존 `items`가 있으면 새 기사로 교체하거나 제거한다. `items`와 뉴스레터 `articleIds`를 둘 다 생략하면 HTML의 요약 있는 기사 링크 순서로 편성한다. `/signage/setup/`의 뉴스레터 선택은 기사 필터이며 세션의 제목·월호를 자동 변경하지 않는다. 사이트 설정 파일에도 위 값을 반영해야 한다.

4. 사이트를 배포하면 실행 중인 앱이 변경을 확인해 반복 경계에서 교체한다. 2·3·4대 구성이 모두 같은 방식을 사용한다.

월호도 `format: "html"` 뉴스레터의 기사 링크 안 `<p>`를 요약으로 읽는다. 기사만 등록하고 뉴스레터에 요약을 넣지 않으면 편성 목록과 재생에서 제외된다. 기존 모든 기사에 별도 요약 필드를 필수로 요구하지 않는다.

앱 1.2.1부터 월호에 `Vol.`을 붙이지 않는다. 이전 앱에서도 문자열 데이터는 읽지만 `Vol. 9월호`로 표시하므로, 정확한 표시를 위해 최초 한 번 1.2.1을 설치한다. 이후 월호나 기사 변경에는 재설치·재실행이 필요 없다.

학내 배포는 수신 대상의 구분이다. 현재 사이트에 게시하는 월호와 사이니지 JSON은 공개 URL이므로 학내 전용 접근 제한을 제공하지 않는다. 비공개 정보는 넣지 않는다.
