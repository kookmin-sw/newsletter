# 콘텐츠와 재생 설정

## 웹에서 2대·3대·4대 편성하기

1. `/signage/setup/`를 연다. 미리보기의 **디스플레이 편성** 링크 또는 기존 디스플레이 생성기에서 이동할 수 있다.
2. **2대 · 한 쌍**, **3대 · 한 쌍** 또는 **4대 · 두 쌍**을 선택한다. 2대는 목록 1대와 상세 1대, 3대는 목록 1대와 상세 2대, 4대는 2대 구성을 두 세션으로 나눈다.
3. 공개 뉴스레터에 요약이 있는 기사를 제목으로 검색하거나 뉴스레터로 필터링한다. 체크박스로 선택하고 **A에 추가**, **B에 추가** 또는 **A·B 반씩 편성**을 누른다. 뉴스레터 필터는 해당 뉴스레터의 `articleIds`를 사용하며, 없으면 HTML 요약의 기사 링크를 사용한다. 필터 선택만으로 세션 호수나 제목이 바뀌지는 않는다.
4. 각 쌍에서 순서 화살표, 기사 삭제, 목록 비우기, 개별 초 입력 또는 전체 재생시간 선택으로 편집한다.
5. **편성 미리보기**를 누른다. 세션 선택으로 A·B를 바꿔 보며 각 기사를 확인한다. 편성을 다시 수정하면 이전 미리보기는 닫힌다.
6. **설정 파일 다운로드**로 받은 `signage.json`을 저장소의 `src/content/config/signage.json`에 반영한다. **설정 복사**를 눌러 Codex에 붙여 넣거나 내려받은 파일을 지정해 반영하도록 요청해도 된다. 자동 복사가 막힌 브라우저에서는 **내보낼 설정 내용**을 펼쳐 직접 복사한다.
7. 테스트·빌드 후 기존 사이트 배포를 수행한다. Windows에서 세션을 배정하고 실행한다.

편성 화면은 로그인이나 서버 없이 동작하는 정적 웹 도구다. 파일 다운로드는 사이트에 저장하거나 원격 앱에 즉시 적용하는 동작이 아니다. 브라우저 새로고침 전 파일로 내보내야 편집 결과를 보관할 수 있다. 다운로드 파일에는 기사 원문이 아닌 기사 ID, 순서, 시간과 세션 설정만 포함된다.

2대 또는 3대에서 4대로 전환하면 기존 순서의 앞 절반은 A, 뒤 절반은 B로 나눈다. 홀수 개면 A가 하나 더 많다. 4대에서 2대 또는 3대로 전환하면 A 다음 B 순서로 합치되 같은 기사는 한 번만 남긴다. 같은 기사의 시간이 두 쌍에서 다르면 B의 시간을 사용한다. 선택 기사로 반씩 편성하면 두 쌍의 기존 목록을 교체한다. A 또는 B에 추가할 때는 그 쌍에 이미 있는 기사를 중복 추가하지 않는다.

원래 첫 두 세션의 ID와 호수·제목·시작 시각·전환 시간을 유지하며, 새 B 세션은 A의 기본 정보를 사용한다. 세 번째 이후의 세션은 파일에 보존한다. 4대에서 2대 또는 3대로 내보내면 원래 두 번째 세션은 제거되므로, 운영 중인 B 모니터는 먼저 사용하지 않음으로 배정하거나 다른 세션으로 옮긴다.

각 쌍에 1~100개 기사, 기사당 5~600초가 필요하다. 빈 쌍이나 잘못된 시간은 미리보기와 다운로드를 막는다. 공개 기사 중 화면 규격에 맞지 않는 제목·요약 또는 잘못된 이미지가 있으면 해당 기사의 수정 이유를 표시하고 선택을 막는다. 초안 기사와 뉴스레터 요약이 없는 기사는 목록에 나타나지 않는다. 설정에 남아 있는 기사도 뉴스레터 요약이 없으면 재생 데이터에서 제외한다. 세션 전체에 요약이 있는 기사가 하나도 없으면 빈 화면을 배포하지 않도록 빌드를 중단한다. 미리보기는 선택한 기사들의 이미지와 글꼴만 준비하며 운영 피드를 주기적으로 받아 편집 결과를 덮어쓰지 않는다.

## 설정 파일

`src/content/config/signage.json`을 수정한다. JSON에는 주석을 넣지 않는다. 알 수 없는 설정 키는 빌드 오류로 처리해 오타를 방지한다.

```json
{
  "schemaVersion": 3,
  "pollIntervalSeconds": 60,
  "sessions": [
    {
      "id": "lobby-a",
      "newsletterId": "newsletter-003",
      "title": "KMUCS 3호 뉴스레터",
      "issue": "003",
      "dateLabel": "2026.10",
      "startsAt": "2026-10-10T00:00:00+09:00",
      "defaultDurationSeconds": 20,
      "transitionMilliseconds": 950,
      "items": [
        { "articleId": "2026-ai-competency-interview" },
        { "articleId": "2026-alumni-panel-talk", "durationSeconds": 30 }
      ]
    }
  ]
}
```

위 예시는 첫 기사 20초, 두 번째 기사 30초, 합계 50초를 반복한다. 전환 950ms는 각 기사의 재생 시간에 포함된다.

| 항목 | 의미와 제한 |
| --- | --- |
| `schemaVersion` | 현재 `3`, 뉴스레터의 긴 요약과 폰트 자동 맞춤은 앱 1.2.0 이상이 필요하다. 기존 `1`·`2`도 앱에서 지원한다. 편성 도구는 버전 3을 유지한다. |
| `pollIntervalSeconds` | 원격 변경 확인 간격. 15~3600초, 기본 설정 60초. |
| `sessions` | 독립 세션 1~20개. 빈 설정은 배포하지 않는다. |
| `id` | 세션의 고유 ID. 영문 소문자·숫자·하이픈, 최대 100자. 변경하면 새 세션이다. |
| `newsletterId` | 공개된 뉴스레터 파일명에서 확장자를 뺀 ID. |
| `title` | 화면 상단 부제, 최대 60자. |
| `issue` | 숫자 문자열 `"003"`은 `Vol. 003`, `"9월호"`는 그대로 표시한다. 최대 20자. 월호 표시는 앱 1.2.1 이상. |
| `dateLabel` | 화면에 표시할 발행일 문구, 최대 30자. 시계 계산에는 쓰지 않는다. |
| `startsAt` | 최초 재생 기준 시각. `Z` 또는 `+09:00` 같은 시간대가 필수다. |
| `detailCount` | 상세 화면 수. 생략 또는 `1`은 기존 구성, `2`는 목록 1대와 상세 2대. `2`는 schemaVersion 2 이상이 필요하다. |
| `defaultDurationSeconds` | 세션의 기사당 기본 시간. 5~600초. |
| `transitionMilliseconds` | 이동·페이드 시간. 0~2000ms. `0`이면 즉시 전환한다. |
| `items` | 선택 사항. 있으면 지정한 순서만 재생. 1~100개, 중복 기사 금지. |
| `items[].articleId` | 공개된 기사 파일명에서 확장자를 뺀 ID. |
| `items[].durationSeconds` | 해당 기사만 시간을 덮어쓴다. 생략하면 세션 기본값 사용. |

`items`를 생략하면 뉴스레터 frontmatter의 `articleIds` 순서를 사용한다. `articleIds`도 없으면 HTML 요약의 기사 링크 순서를 사용한다. 순서를 자동으로 최신순 정렬하지 않는다.

```yaml
articleIds:
  - 2026-ai-competency-interview
  - 2026-alumni-panel-talk
  - 2026-career-week
```

다른 호수를 쓰려면 세션의 `newsletterId`와 호수 표시를 바꾸고, 이전 `items`가 있으면 새 기사 목록으로 교체하거나 제거한다. 기사 수가 6개를 넘으면 앞 페이지부터 최대 6개씩 채운다. 마지막에 1개만 남을 때만 앞 페이지에서 하나를 옮긴다(7개는 5+2, 8개는 6+2, 13개는 6+5+2). 페이지 사이 기사는 중복하지 않으며 마지막 페이지의 기사 번호도 전체 순서를 따른다. 이 분할은 앱 1.2.2부터 적용한다.

## 제목과 요약 수정

상세 요약의 원본은 `/news/newsletter-003/` 같은 **뉴스레터 페이지의 기사 카드 본문**이다. 해당 페이지를 만드는 `src/content/news/newsletter-003.md`의 HTML에서 기사 링크 안에 있는 `<p>`를 읽고 `<br><br>` 문단 구분을 보존한다. 문장을 재작성하거나 생략하지 않는다. 빌드 시 동일한 저장소 콘텐츠로 사이트와 `/signage/feed.json`을 만들며, Windows 앱이 운영 사이트 HTML을 직접 긁어 오지는 않는다.

우선순위는 세션의 `newsletterId`에 해당하는 요약, 그 기사가 실린 가장 최근 공개 HTML 뉴스레터의 요약이다. 두 곳 모두 없으면 편성 목록과 재생 데이터에서 제외한다. 기사의 `excerpt`나 목록 소개로 대체하지 않는다. 같은 기사가 여러 호수에 실리면 지정한 호수의 요약을 우선한다. 편성 미리보기도 같은 규칙을 사용한다. 초안 뉴스레터는 제외한다.

뉴스레터를 수정하고 사이트를 배포하면 새 revision이 생기며 앱이 기존 폴링과 반복 경계에서 반영한다. 4호도 같은 HTML 기사 카드 형식이면 자동 추출된다. `articleIds`가 없는 HTML 뉴스레터는 요약이 있는 기사 링크 순서를 기본 기사 목록으로 사용한다. 이미지로만 된 과거 뉴스레터에서는 요약을 추출하지 않는다.

기사 제목·목록 소개는 기사 frontmatter에서 수정한다. 상세 요약을 추가하려면 공개 HTML 뉴스레터에 해당 기사 링크와 요약 문단을 작성한다.

```yaml
title: "화면에 표시할 기사 제목"
displayExcerpt: "목록에서 읽는 짧은 한 줄 소개"
coverImage: "/images/articles/example.webp"
```

- 목록 소개는 `displayExcerpt → excerpt → subtitle` 순서로 선택한다. `displayExcerpt`는 최대 100자다. 가독성을 위해 40~60자 내외를 권장한다.
- 상세 요약은 공개 HTML 뉴스레터에서만 읽는다. 사용하지 않는 기사별 `displaySummary` 필드는 제거했다. 뉴스레터 요약이 없으면 표시하지 않는다.
- 버전 3의 뉴스레터 요약은 1~4문단, 합계 800자 이하다. 초과하면 조용히 자르지 않고 빌드 또는 편성 검증에서 거절한다. 버전 1·2 데이터는 기존 합계 480자 제한을 유지한다.
- 재생할 기사의 제목은 140자 이하, 소개는 180자 이하다. 제목과 목록 소개는 자동 축소하거나 잘라내지 않으므로 길면 직접 다듬는다. 상세 요약은 내용 전체를 유지하고 폰트만 자동 축소한다.
- 태그는 앞의 3개를 사용하고 각 24자 이하다.
- 대표 이미지는 저장소 `public/images/` 아래 PNG/JPEG/WebP/SVG를 사용한다. 외부 URL과 경로 이동(`..`)은 거절한다. 이미지가 지정되지 않은 기사는 KMUCS 대체 화면을 보여준다.
- 기사 QR은 사이트의 `/articles/<articleId>/` 링크에서 빌드 시 자동 생성된다. 요약은 공개 JSON에도 들어가므로 공개 가능한 내용만 넣는다.
- `draft: true` 기사와 뉴스레터는 재생 데이터에 넣을 수 없다.

본문 요약·목록 설명 등 보통 굵기의 글자는 `public/fonts/Pretendard-Regular.woff2`, 굵은 기사 제목은 `KMU-Bold.ttf`를 사용한다. Pretendard 1.3.9 공식 파일과 SIL OFL 라이선스(`Pretendard-LICENSE.txt`)를 함께 보관한다. 상단 영문 표제와 숫자는 플레이어의 Arial 설정을 따른다. 외부 폰트 CDN 없이 오프라인 재생할 수 있다.

폰트 경로는 `src/lib/signage.ts`의 `branding`에서 지정한다. 경로 또는 파일이 바뀌면 빌드가 새 해시와 피드 revision을 생성한다. 기존 Windows 앱도 새 파일을 검증·캐시한 뒤 반복 경계에서 교체하므로, 이 폰트 변경에는 앱 재설치·재실행이 필요 없다.

## 모니터 3대, 세션 1개

웹 편성에서 **3대 · 한 쌍**을 고르면 현재 `schemaVersion: 3`과 해당 세션의 `detailCount: 2`가 내보내기에 포함된다. Windows 앱 1.2.0 이상을 처음 한 번 설치하고 사이트 설정을 배포한 다음, 앱에서 3대 빠른 배정을 사용한다.

| 모니터 | 세션 | 역할 |
| --- | --- | --- |
| 1 | lobby-a | 뉴스 목록 |
| 2 | lobby-a | 뉴스 상세 1 (`detail`) |
| 3 | lobby-a | 뉴스 상세 2 (`detail-secondary`) |

목록은 같은 페이지 안에서 두 기사를 함께 강조한다. 파란색 1과 민트색 2가 상세 화면의 번호와 대응한다. 두 기사의 재생 시간이 다르면 더 긴 시간을 사용하고 함께 전환한다. 페이지에 홀수 개가 있으면 그 페이지의 마지막 두 기사를 함께 보여준다(7개: 목록 1~5에서 1·2 → 3·4 → 4·5, 목록 6~7에서 6·7). 8개는 1·2 → 3·4 → 5·6 → 7·8이다. 끝에서 두 번째 기사는 한 번 더 표시하며 서로 다른 페이지의 기사나 첫 기사와 마지막 기사를 섞지 않는다. 기사 1개는 상세 두 화면에 같은 기사를 표시한다.

3대 구성을 유지한 채 다음 호수, 기사, 요약, 순서나 시간을 바꾸면 사이트 배포 후 실행 중인 앱이 자동 반영한다. 2대와 3대 사이의 구성 변경은 실제 모니터 역할도 달라지므로 앱 설정에서 한 번 재배정한다. 버전 3을 지원하지 않는 구버전 앱은 새 데이터를 거절하고 마지막 정상 콘텐츠를 유지한다.

## 모니터 4대, 세션 2개

기존 세션 객체를 복사해 `id`를 `lobby-b`로 바꾸고 원하는 기사와 시간을 지정한다. 앱 설정에서 다음처럼 배정한다.

| 모니터 | 세션 | 역할 |
| --- | --- | --- |
| 1 | lobby-a | 뉴스 목록 |
| 2 | lobby-a | 뉴스 상세 |
| 3 | lobby-b | 뉴스 목록 |
| 4 | lobby-b | 뉴스 상세 |

같은 세션의 목록이나 상세를 여러 모니터에 복제할 수도 있다. 각 사용 세션에는 목록과 상세 역할이 모두 있어야 저장된다. 실제 모니터 배정은 PC 로컬 설정이며 Git에 저장하지 않는다.

## 변경 반영과 기준 시각

기사·설정·이미지 내용으로 데이터 `revision`을 자동 생성한다. 파일 이름이 같아도 이미지 내용이 바뀌면 다른 버전이다. 사용자가 revision을 편집하지 않는다.

새 데이터는 파일 해시 검증, 이미지 디코딩, 글꼴 로딩, 모든 실행 창의 준비 확인을 거친다. 그 후 최소 2초의 여유를 두고 각 세션의 다음 반복 시작점에 반영한다. 경계까지 2초 이하가 남았다면 한 바퀴 더 기다릴 수 있다. 새 버전을 준비하는 동안 현재 재생은 계속된다.

일반적인 기사·시간 변경에서는 새 목록의 1번 기사부터 시작한다. `startsAt` 자체를 변경했다면 새 기준 시각의 현재 위치를 계산한다. 미래 시각이면 시작 대기 문구를 표시한다. 매번 콘텐츠를 바꿀 때 `startsAt`을 바꿀 필요는 없다.

반영 지연에는 사이트 배포 시간, CDN 갱신, 확인 주기, 다운로드 시간, 반복 경계 대기가 포함된다. 배포 직후 즉시 전환을 보장하지 않는다. 준비 확인이 45초 안에 완료되지 않으면 기존 콘텐츠를 유지하고 오류를 표시한다.

설정에서 세션을 삭제해도 그 세션이 배정된 화면은 마지막 정상 콘텐츠를 유지한다. 먼저 모니터를 다른 세션에 배정하거나 사용하지 않음으로 저장한 뒤 세션을 정리한다. 세션 ID 변경 역시 모니터 재배정이 필요하다.

## 배포 전 확인

```sh
pnpm test:signage
pnpm check:signage
pnpm build
```

`/signage/`의 번호 버튼으로 모든 기사 화면을 확인한다. 번호 버튼은 브라우저 미리보기만 고정하며 운영 설정을 바꾸지 않는다. 모니터 한 장 형태로 확인하려면 다음 주소를 사용한다.

```text
/signage/?session=lobby-a&role=list
/signage/?session=lobby-a&role=detail
/signage/?session=lobby-a&role=detail-secondary
```

잘못된 설정은 빌드에서 실패한다. 변경이 게시되지 않으면 현재 배포와 재생 데이터는 유지된다. 롤백은 관련 Git 변경을 되돌리고 다시 배포한다.

## 화면 구성

목록은 기사 수와 관계없이 사진 없는 텍스트 카드만 표시한다. 한 페이지에 최대 6개이며, 1~5개는 5개 배치 기준의 동일한 카드 크기와 글꼴을 사용한다. 6개일 때만 카드 높이를 줄인다. 카드는 위쪽부터 배치하고 남는 아래 공간은 비운다. 마지막 페이지에도 같은 규칙을 적용한다.

상세 대표 사진은 가운데를 기준으로 영역을 채우도록 크롭한다(`object-fit: cover`). 제목이나 얼굴이 가장자리에 있는 사진은 미리보기에서 잘림을 확인한다. 목록 화면에는 alumni 사이트 QR을 표시하고, 상세 화면에는 기사 원문 QR만 표시한다. 상세 하단은 왼쪽 태그와 오른쪽 150×150px QR을 같은 행에 하단 정렬하고 구분선과 별도 안내 문구는 표시하지 않는다. 크기는 1080×1920 기준이며 화면과 함께 비례 조정된다.

상세 화면은 제목 영역 204px와 사진 위치를 고정하고 요약을 위쪽에 정렬한다. 제목 영역과 사진 사이 간격은 28px, 사진과 요약 사이는 36px다. 요약 전체가 140자 이하이면 최대 36px, 210자 이하이면 최대 33px, 그보다 길면 최대 30px에서 시작한다. 실제 본문 영역을 측정해 들어갈 때까지 1px씩 줄이며 하한은 16px다. 문장이나 문단을 삭제하지 않고 한 화면에 표시한다. 480자를 넘는 요약은 행간 1.5, 문단 간격 16px를 사용한다. 2026-10-10 검수 시 3호의 실제 요약 7개는 23~25px로 들어갔다. 짧은 본문 때문에 사진 위치가 이동하지 않는다.

## 전환 모션

기본 전환 시간은 950ms다. 목록 강조 테두리는 처음과 끝에서 천천히 움직이고 카드 색도 같은 진행률로 바뀐다. 같은 페이지의 마지막 기사에서 첫 기사로 돌아갈 때는 목록을 유지한 채 선택 표시만 사라졌다 나타난다. 페이지 자체가 바뀔 때에만 목록을 교체한다.

상세 화면은 이전 글자를 먼저 지운 뒤 제목, 요약 문단, 하단 정보 순서로 나타낸다. 사진은 고정된 영역에서 교차 페이드와 작은 확대·축소를 사용한다. 제목 영역의 높이를 고정해 기사마다 사진 위치가 튀지 않게 한다. 모든 단계는 `transitionMilliseconds`의 비율로 계산되며 추가 타이머를 만들지 않는다. 모션 감소 설정 또는 전환 시간 0에서는 즉시 표시한다.
