# Windows 설치와 운영

## 설치 파일 만들기

사이트를 먼저 배포해 `https://alumni.cs.kookmin.ac.kr/signage/feed.json`이 열리는지 확인한다. 새 앱의 첫 실행에는 이 주소에서 데이터를 받아야 한다. 네트워크를 끊은 첫 실행에는 표시할 콘텐츠가 없다.

설치 파일은 [GitHub Releases](https://github.com/kookmin-sw/newsletter/releases)에서 받는다. 해당 버전의 **Assets**에서 `KMUCS.News.Sinage.Setup.<버전>.exe`를 내려받는다. `Source code` 파일은 설치 파일이 아니다. 공개 저장소이므로 다운로드에 GitHub 로그인이 필요하지 않다.

새 버전을 게시하려면 `apps/signage-desktop/package.json`의 `version`을 올리고 변경 사항을 커밋해 `main`에 푸시한다. 그 커밋에 버전과 일치하는 태그를 만들어 푸시한다. 예를 들어 앱 버전이 `1.2.1`이라면 다음과 같다.

```sh
git tag signage-v1.2.1
git push origin signage-v1.2.1
```

**Build Windows Signage**가 Windows에서 테스트·타입 검사·빌드 후 설치 파일과 `SHA256SUMS.txt`를 GitHub Release에 자동 게시한다. 태그와 앱 버전이 다르면 실패한다. 기존 릴리스 파일을 덮어쓰지 않으므로 수정본은 버전을 올려 새 태그로 배포한다. 앱 빌드에는 읽기 권한만 부여하고 릴리스 게시 작업에만 저장소 쓰기 권한을 부여한다.

게시 없이 빌드만 시험하려면 GitHub Actions에서 **Build Windows Signage**를 `main` 브랜치로 수동 실행한다. 성공하면 `kmucs-signage-windows-x64` 아티팩트에서 설치 파일을 받을 수 있다. 설치 파일 배포는 GitHub Releases를 사용하며 Packages나 별도 배포 서버는 필요 없다.

Windows 개발 PC에서 직접 만들려면 다음 명령을 사용한다.

```sh
pnpm install --frozen-lockfile
pnpm test:signage
pnpm check:signage
pnpm signage:dist
```

출력 위치는 `apps/signage-desktop/release/`다. 현재 대상은 Windows x64다. 앱 버전은 `apps/signage-desktop/package.json`의 `version`으로 관리하며 새 설치 파일 배포 시 올린다.

현재 코드 서명 인증서를 설정하지 않았으므로 Windows가 게시자 미확인 또는 SmartScreen 확인을 표시할 수 있다. 학교의 설치 정책을 확인한다. 설치 파일 이름, 출처와 빌드 결과를 확인한 뒤 설치한다. 코드 서명 도입 시 인증서와 비밀은 Git에 넣지 않고 CI secret으로 관리한다.

## 최초 설정

1. 모니터를 PC에 연결하고 Windows 디스플레이 설정을 **확장**으로 지정한다.
2. 각 모니터의 방향을 **세로**, 가능하면 해상도를 **1080×1920**으로 설정한다.
3. KMUCS News Sinage를 실행하고 콘텐츠 수신이 완료될 때까지 기다린다.
4. **모니터 한 번에 배정**에서 2대, 3대 또는 4대 구성과 A·B 세션을 선택하고 **빠른 배정**을 누른다. 아래 모니터 카드 순서로 목록·상세를 배정한다. 모니터 이름·ID·해상도를 보고 실제 위치와 다르면 각 카드에서 수정한다.
5. 같은 세션에 목록과 상세를 각각 배정한다. 3대 구성은 상세 1과 상세 2를 모두 배정하고 **저장하고 실행**을 누른다.
6. 모든 화면이 준비되면 각 모니터의 전체 화면으로 표시된다.
7. 필요하면 **Windows 로그인 후 자동 실행**을 체크하고 저장한다.

빠른 배정은 로컬 설정 초안만 바꾸며 **저장하고 실행** 전까지 재생 화면은 바뀌지 않는다. 선택한 2대, 3대 또는 4대 외 모니터의 기존 배정은 해제한다. 연결된 모니터가 부족하면 버튼을 사용할 수 없고, 두 쌍에는 서로 다른 세션을 선택해야 한다. 3대 구성의 `detailCount: 2` 설정 또는 4대 구성의 두 번째 세션이 없으면 먼저 웹 편성에서 설정 파일을 만들고 사이트에 배포한다.

자동 실행은 설치된 Windows 앱에서 적용된다. 부팅만으로는 실행되지 않고 Windows 사용자 로그인이 필요하다. Windows 자동 로그인 정책은 이 앱이 변경하지 않는다. 앱은 실행 중 화면 꺼짐을 억제하지만 강제 잠금, Windows Update 재부팅, 전원 차단을 막지는 않는다.

Windows 배율이 125% 또는 150%여도 전체 콘텐츠를 창 크기에 맞춰 비율을 유지한다. 가로 모니터에서는 좌우 여백이 생긴다. 방향과 배율을 바꾼 뒤 실제 글자 크기를 확인한다.

## 전체 화면과 단축키

| 조작 | 기능 |
| --- | --- |
| `Ctrl + Alt + S` | 설정 창 열기 |
| `Ctrl + Alt + Q` | 앱 전체 종료 |
| 설정 창 닫기 | 재생 창이 있으면 설정 창만 숨김 |
| 설정의 앱 종료 | 모든 재생 창 종료 |

재생 창은 테두리 없는 키오스크 전체 화면이며 마우스 커서를 숨긴다. `Esc`, `F11`로 임의로 창 모드로 바뀌지 않는다. OS 수준 접근 제어 기능은 아니므로 Windows 작업 관리자 등은 별도 정책으로 관리한다. 단축키가 다른 프로그램과 충돌하면 재생 창에 포커스를 둔 상태에서 다시 누른다.

앱 1.2.2부터 Windows 재생 창은 작업표시줄보다 위에 유지한다. 설정 창도 재생 창 위로 열리므로 `Ctrl + Alt + S`로 접근하고 창을 닫아 재생 화면으로 돌아갈 수 있다. Windows 작업표시줄 설정 자체는 변경하지 않는다. 이전 버전에서 작업표시줄이 보이면 앱을 종료하고 1.2.2 이상 설치 파일로 업데이트한다.

## 로컬 저장과 오프라인

설정 창 하단에 실제 캐시 경로가 표시된다. Windows에서는 일반적으로 `%APPDATA%\KMUCS Signage` 아래에 저장된다.

1.2.3부터 앱 이름은 `KMUCS News Sinage`이며 국민대학교 원형 로고를 아이콘으로 사용한다. 기존 설치본을 업그레이드해도 모니터 배정과 캐시를 읽도록 앱 ID와 위 저장 경로는 유지한다. 새 앱의 첫 실행에서 저장된 자동 실행 설정을 새 실행 파일 경로로 갱신한다.

| 파일 또는 폴더 | 내용 |
| --- | --- |
| `settings.json` | 모니터 ID·세션·역할과 자동 실행 선택 |
| `playback.json` | 마지막 정상 재생 데이터, 적용 대기 데이터와 기준 시각 |
| `assets/` | 해시로 구분한 이미지와 글꼴 |

정상 콘텐츠를 한 번 받은 뒤에는 인터넷이 끊겨도 재생하며, 앱을 껐다 켜도 캐시로 복구한다. 파일 저장은 임시 파일을 쓴 뒤 이름을 바꿔 처리한다. 캐시를 읽을 때 이미지·글꼴 해시를 검증한다.

새 설정을 받지 못하거나 준비가 실패하면 기존 콘텐츠를 유지한다. 인터넷이 돌아오면 주기적으로 다시 확인한다. 설정의 **콘텐츠 다시 확인**으로 확인을 앞당길 수도 있다. 이미 준비 중이거나 전환 시각을 기다리는 동안에는 중복 갱신을 실행하지 않는다.

사용하지 않는 에셋과 중단된 다운로드의 임시 파일은 준비 작업이 끝난 뒤 정리한다. 삭제된 세션은 모니터 배정이 남아 있는 동안만 마지막 재생 데이터와 에셋을 보존한다. 배정을 해제하면 자동 정리한다. 장기간 운영 후 수동 캐시 초기화가 필요하면 앱을 종료하고 해당 폴더를 백업한 뒤 정리한다. 초기화 후에는 온라인에서 다시 받아야 한다.

## 장애 대응

| 현상 | 확인과 조치 |
| --- | --- |
| 첫 실행에서 콘텐츠 없음 | feed URL의 배포 여부, HTTPS 접속, 방화벽 확인. 이후 콘텐츠 다시 확인. |
| 새 설정이 바로 반영되지 않음 | 배포 완료, 확인 주기와 기존 반복 경계 대기 확인. 준비 오류 메시지 확인. |
| 이미지 또는 폰트 버전 불일치 | 배포/CDN 갱신이 끝난 뒤 재확인. JSON만 수동 수정하지 않기. |
| 모니터가 연결되지 않았다는 안내 | 케이블과 Windows 확장 모드 확인. 같은 ID로 다시 연결하면 자동 복구. |
| 모니터 ID가 달라짐 | 설정에서 연결 해제된 배정을 지우고 새 모니터에 다시 배정. |
| 한 세션에 역할이 부족하다는 오류 | 해당 세션에 목록과 상세를 모두 지정. 3대 구성은 상세 2도 필요. |
| 지원하지 않는 schemaVersion | 새 앱 설치 또는 사이트 설정 롤백. |
| 텍스트가 겹치거나 넘침 | 웹 미리보기에서 기사 확인 후 제목·요약을 줄이고 재배포. |
| 반복적인 재생 창 종료 | 앱이 최대 3번 복구 시도 후 설정을 표시. 앱 재시작, 그래픽 드라이버와 메모리 확인. |
| 오프라인 복구 실패 | 캐시 삭제·손상 여부 확인. 온라인에서 다시 수신. |

앱은 alumni 사이트에 HTTPS로 나가는 연결만 사용한다. 학교 PC로 들어오는 포트를 열거나 별도 서버를 실행하지 않는다.

## 앱 업데이트

뉴스레터 원문 요약과 폰트 맞춤은 앱 1.2.0 및 데이터 버전 3부터 지원한다. 앱을 먼저 업그레이드한 뒤 버전 3 피드를 배포한다. 이후 뉴스레터 요약 수정은 사이트 배포만으로 반영하며 재설치나 재실행이 필요 없다.

기사·요약·설정 변경은 사이트만 배포한다. 화면 코드·시간 계산 코드·Electron 변경은 새 설치 파일을 만든다. 앱을 종료한 뒤 새 버전을 설치하고 모니터 배정과 재생을 확인한다. 자동 앱 업데이트는 아직 포함하지 않는다.

## 개발용 주소

개발 서버 포트가 4322라면 PowerShell에서 다음처럼 실행한다.

```powershell
$env:SIGNAGE_FEED_URL = "http://localhost:4322/signage/feed.json"
pnpm signage:demo
```

macOS/Linux 셸에서는 다음과 같다.

```sh
SIGNAGE_FEED_URL=http://localhost:4322/signage/feed.json pnpm signage:demo
```

개발 모드는 localhost의 HTTP만 허용한다. 다른 주소는 HTTPS가 필요하다. 개발 앱 데이터는 `KMUCS Signage Dev`에 분리된다. 자동 테스트에서는 `SIGNAGE_USER_DATA_DIR`로 임시 저장 폴더를 지정할 수 있으며 이 변수는 개발 모드에서만 적용된다.

월호 표시는 앱 1.2.1부터 지원한다. 기존 앱은 `9월호` 데이터를 읽지만 `Vol. 9월호`로 표시한다. 최초 한 번 1.2.1을 설치한 뒤에는 숫자 호수와 월호 사이를 바꿀 때도 재설치·재실행 없이 사이트 배포로 교체한다. 월호 등록과 설정 예시는 [운영 안내](README.md#숫자-호수가-없는-월호-발행)를 따른다.
